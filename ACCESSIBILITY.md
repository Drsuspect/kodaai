# Accessibility Statement

KODAAI is committed to voice-first systems that support independent use by blind and visually impaired people.

## Our approach

- Voice is treated as a primary interface.
- Critical actions should not depend on visual feedback alone.
- Keyboard and screen-reader paths are preserved.
- Spoken prompts should be concise, deterministic, and recoverable.
- Ambiguous commands should trigger confirmation or a safe retry.
- Playback speed, pause, resume, and repeat controls should remain locally responsive.
- Accessibility decisions should be tested with target users.

## Current status

KODAAI Education is in private beta and is developed with a 100% accessibility target. This is a design and validation objective, not a claim that every device, browser, content item, or user scenario is already barrier-free.

## Reporting a barrier

When reporting an accessibility issue, describe:

- the affected task;
- device, operating system, browser, or Android version;
- assistive technology in use;
- expected and observed behavior;
- whether the issue blocks independent completion.

Do not include personal information, real user voice recordings, credentials, or production logs in public reports.
